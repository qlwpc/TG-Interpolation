# Paper Pretraining Reproduction Details

This guide covers the historical configuration inventory. The
[revised manuscript](../results/paper.md) retains historical BBC 100M/FineWeb 1B
checkpoint identities but uses the [ten dedup 500M configurations](../../reproducibility/configs/dedup500m/manifest.json)
for its main BBC 500M block. The historical four-model BBC 500M group below is a
separate supplementary comparison.

> When starting a new pretraining task, first follow the [pretraining workflow](pretraining.md). The current BBC default uses
> dedup train + new clean dev/test; the fixed-index and historical-configuration workflow in this document is used only for explicitly selected corresponding reproductions,
> and does not override the data versions, evaluation frequency, W&B, and GPU probing requirements of the new workflow.

Model, corpus, and configuration identities are stored in [paper_pretraining_manifest.json](../../train_configs/paper_pretraining_manifest.json)
and the hash-pinned `paper_sources/`; the generator verifies configuration fields before creating a new run.
These configuration copies are kept separate from the weights directory; paper numbers and interpretation are in the [paper results notes](../results/paper.md).
BBC SEP Pause uses the original submitted configuration copy pinned by SHA-256, and separately registers the final checkpoint identity;
see [`pause_protocol.md`](../models/pause.md) for details.

## 1. Unified data construction entry point

All commands are run from the repository root. First check the parsing dependencies:

```bash
python -m datatools.parse_pretrain_data.setup_parse_deps --check
# Run again only when models are missing; this accesses the network.
python -m datatools.parse_pretrain_data.setup_parse_deps
```

The stable entry point is:

```bash
python -m datatools.parse_pretrain_data.build_pretrain_data <stage> --corpus <bbc|fineweb-edu>
```

`plan` only generates stages, array ranges, paths, and command lists; it does not download data or start computation:

```bash
python -m datatools.parse_pretrain_data.build_pretrain_data plan --corpus bbc
python -m datatools.parse_pretrain_data.build_pretrain_data plan --corpus fineweb-edu
```

Array tasks can take an explicit `--task-index N`, or read it from `SLURM_ARRAY_TASK_ID`. Each command generated by `plan`
preserves the custom raw/parsed/tokenized/final/tokenizer paths and provides a copyable `shell_command`.
It is not a job submitter: subsequent stages must run only after all download/parse array tasks have succeeded.

Downloads use temporary files with full-length checks before replacement; parsing resumes by complete document lines and writes a `.parse.json` completion record.
The three-way tokenization is reused only when the SHA-256 of the source text, tokenizer, and all three outputs match the completion record;
it no longer skips based merely on file existence. Existing tokenizers are by default validated for layout and reused, without rebuilding online.

The current tokenization protocol is `explicit-bos-eos-atomic-tree-ptb-v2`.
It inserts registered structural IDs explicitly and binds each receipt to the
bracket policy: BBC preserves PTB escapes; FineWeb/Qwen restores native brackets,
including embedded forms. Earlier v1 receipts are rejected rather than relabeled.
Rebuilding with this corrected converter is a new data build, not proof of the
historical training bytes. Keep historical arrays and their identities intact.

### 1.1 BBC News (FineWeb BBC subset)

The 94 Common Crawl configs in a fixed order are stored in
[`bbc_configs.txt`](../../datatools/parse_pretrain_data/bbc_configs.txt). The full chain is:

```text
permutans/fineweb-bbc-news parquet
  -> benepar_en3_large + spaCy sentence splitting
  -> dataset/bbc-news-parsed/<config>.txt (one line per document)
  -> GPT-2 extended tokenizer
  -> dataset/bbc-news-shards/{tree,terminal,tg}/<config>.npy (uint16)
  -> train/dev/test.npy with fixed document split
  -> Tree-NoONT / Tree-Compress / Tree-TripleCNT
  -> TreeReg / Pushdown parse-aligned data
```

Stage commands:

```bash
# tokenizer; paper files should yield vocab=50320, SEP=50261.
python -m datatools.parse_pretrain_data.build_pretrain_data tokenizer --corpus bbc

# Scheduler array 0-93: each item downloads and parses the same config respectively.
python -m datatools.parse_pretrain_data.build_pretrain_data download --corpus bbc --task-index "$TASK_ID"
python -m datatools.parse_pretrain_data.build_pretrain_data parse    --corpus bbc --task-index "$TASK_ID"

# After all parsing is complete, generate the LIN1 tree / terminal / LIN2 tg three-way shards at once.
python -m datatools.parse_pretrain_data.build_pretrain_data tokenize --corpus bbc --jobs 1
```

The repository already contains the original `dataset/bbc-news/dev_index.json` and `test_index.json`; no regeneration is needed.
The default `plan` does not include `make-split-indices`; `assemble` reads these two files from the repository's release location
(even if `--final-dir` points to another directory), and verifies SHA-256 against
[`bbc_split_manifest.json`](../../datatools/parse_pretrain_data/bbc_split_manifest.json):

```bash
python -m datatools.parse_pretrain_data.build_pretrain_data validate-splits --corpus bbc
python -m datatools.parse_pretrain_data.build_pretrain_data assemble --corpus bbc
```

The index protocol is as follows:

- dev has 4,980 documents and test has 5,025 documents; each covers 89 configs, with no duplicates or cross-selection.
- The full download/parse set is the 94 shards in `bbc_configs.txt`; the training assembly order uses
  the 89 historical shards in `bbc_train_shards.txt`. Within each config, dev/test documents keep the original order of the JSON list,
  without sorting or converting to sets; train keeps source document order, excluding the union of dev/test.
- `CC-MAIN-2023-{06,14,23,40,50}` are five reserved shards; current assembly explicitly rejects them from entering train.
  "No dev/test index means all included in train" is an old behavior that has been fixed and cannot be used to replace the current protection.
- Unknown configs, duplicate IDs, negative/non-integer values, dev/test overlap, and out-of-range IDs all raise errors directly; missing shards are not skipped.

Before writing any output, `assemble` checks all source/targets, dtype, per-shard document counts, and split ranges.
It scans BOS in chunks, writes standard `.npy` headers with mmap, does not load 20–80 GB arrays into memory, and does not use `cat`
to concatenate `.npy`. The three representations use the same index, each output is atomically replaced after completion, and finally
`assembly_manifest.json` is written, storing tokenizer/index identity, document counts, and output hashes.

Note: the old `gen_final_train.py` appends sentinel documents in place to the index list, and accumulates across representations; the new workflow does not reproduce
this side effect. The provided index pins down "which documents are selected and their order"; it alone cannot prove that the token stream after re-download/re-parse
is byte-for-byte identical to the historical training stream. The existing 4,966-document DocPPL corpus is another evaluation contract and cannot be automatically replaced
by the 5,025-document `test.npy` generated this time; for historical boundaries see [BBC data provenance](../protocols/bbc_data.md#versions).

On 2026-09-06, the 5,025-document old test was reproduced byte-for-byte from the RTX3090 archived parsed documents, and it was verified that the local current
`test.npy` is already the 4,966-document DocPPL-aligned version. The current converter also still has parenthesis encoding differences from the old version; for the old-version compatibility
mode, the 6 body revisions, and the current exact build script, see
[BBC data provenance](../protocols/bbc_data.md#versions).

For a new split experiment, an independent directory must be explicitly specified, and then both custom indices passed in:

```bash
python -m datatools.parse_pretrain_data.build_pretrain_data make-split-indices --corpus bbc \
  --output-dir artifacts/data/custom_bbc_split --seed 42
python -m datatools.parse_pretrain_data.build_pretrain_data assemble --corpus bbc \
  --dev-index artifacts/data/custom_bbc_split/dev_index.json \
  --test-index artifacts/data/custom_bbc_split/test_index.json \
  --final-dir artifacts/data/custom_bbc_streams
```

New indices must not be written into release/final directories, and must not overwrite existing split files; custom results are not labeled as the paper release split.

Generate ablation data and the two architecture baselines:

```bash
python -m datatools.parse_pretrain_data.build_pretrain_data variants --corpus bbc --jobs 4
python -m datatools.parse_pretrain_data.build_pretrain_data baselines --corpus bbc --workers 8
```

`variants` builds `tree_noont/`, `tree_compress/`, `tree_triplecnt/` from LIN1; Tree-Shuffle
is not written to disk and is shuffled online by the collator. `baselines` generates, for train/dev/test respectively,
`parse_aligned/*_treereg` and `*_pushdown_unary_terminals`, using unary collapse, right CNF,
and terminal alignment.

The validation stage distinguishes shards from the final three-way assembled streams, so that "intermediate data was validated" is not misread as "final output was validated":

```bash
python -m datatools.parse_pretrain_data.build_pretrain_data validate --corpus bbc --scope shards
python -m datatools.parse_pretrain_data.build_pretrain_data validate --corpus bbc --scope assembled
python -m datatools.parse_pretrain_data.build_pretrain_data validate --corpus bbc --scope all
```

Shard validation requires an exact filename set, the paper tokenizer layout, completion records, output hashes, dtype, valid token
ranges, BOS/EOS, and document counts; assembled validation reads the completion manifest and verifies the shape, dtype, and hash of the nine outputs.
`variants`/`baselines` also check the assembly results before running. `--scope all` does not validate derived ablations or TreeReg/Pushdown
supervision semantics; they are generated by their respective precomputation programs, and the campaign's `--validate-data` continues to perform path checks.

The logical length of the historical BBC terminal `train.npy` is `10,061,025,584` `uint16` tokens;
LIN1/LIN2 are approximately 24.7B/32B. The logical length must be read from the NumPy header, and cannot be obtained by dividing physical bytes by 2.

### 1.2 FineWeb-Edu-100BT

The chain is:

```text
HuggingFaceFW/fineweb-edu:sample-100BT
  -> traceable staging directory of the datasets Arrow cache
  -> 984 Arrow shards / 246 parse tasks, each covering four shards
  -> benepar_en3 + spaCy sentence splitting
  -> Qwen3 extended tokenizer
  -> dataset/fineweb-edu-v2/{tree,terminal,tg}/246 shards (uint32)
```

Stage commands:

```bash
# Paper files should yield vocab=151732, SEP=151673; token ids exceed uint16.
python -m datatools.parse_pretrain_data.build_pretrain_data tokenizer --corpus fineweb-edu

# Download sample-100BT, and pin the datasets cache Arrow files into the staging directory via symlinks.
python -m datatools.parse_pretrain_data.build_pretrain_data download --corpus fineweb-edu

# Scheduler array 0-245; task i always processes the four Arrow shards [4i, 4i+1, 4i+2, 4i+3].
python -m datatools.parse_pretrain_data.build_pretrain_data parse --corpus fineweb-edu --task-index "$TASK_ID"

python -m datatools.parse_pretrain_data.build_pretrain_data tokenize --corpus fineweb-edu --jobs 1
python -m datatools.parse_pretrain_data.build_pretrain_data validate --corpus fineweb-edu
```

To make staging independent of the Hugging Face cache, add `--copy-cache-files` during the download stage, but this takes additional
disk space close to the entire corpus. FineWeb-Edu pretraining directly consumes the 246 shard patterns and no longer concatenates them into a single
train.npy. Paper token amounts are approximately terminal 98B, LIN1 233B, and LIN2 301B.

BBC uses `benepar_en3_large`, while the historical FineWeb-Edu workflow uses `benepar_en3`; this is a registered historical
difference, and the models are not silently unified when reproducing old data.

The later [FineWeb audit and repairs](../protocols/fineweb_edu_data.md) concern a
local terminal/Tree corpus with headerless uint32 storage and EOS-only boundaries.
Those repaired arrays and the [filtered 20B subset](../protocols/fineweb_clean_20b.md)
are separate from this historical training recipe and from newly generated
standard NPY shards. Known ADJ-label leakage remains unrepaired in those local
datasets; this release does not replace the paper's frozen configuration inputs.

### 1.3 Failures, recovery, and reproduction boundaries

- Both parsers are compatible with standard Benepar's single `Tree` and the historical top-k candidate list, and check sentence counts and complete
  terminal yields. The standard interface cannot directly take `tree[0]`. FineWeb Arrow filenames are sorted before loading.
- `parse --max-docs N` applies to both corpora and is only for small-sample checks; shards whose completion record is partial
  cannot enter the unified entry point's `tokenize`. Remove the limit and resume until all documents are complete before tokenization.
- Empty/bad tree lines, unfinished last lines, and embedded BOS/EOS all make tokenization fail; lines are not silently deleted.
  BBC empty-document sentence splitting also raises an error; it must not be "fixed" by filtering, otherwise the release index will shift.
- Tokenization memory is used per document and in fixed copy chunks; temporary disk must hold one shard's three-way raw + NPY
  output, approximately twice the total size of the shard's three-way output. `--jobs` defaults to 1; increase it according to disk space and I/O budget.
- Old shards/half-finished products without completion records are not automatically reused; after explicitly verifying the path, `tokenize --overwrite`
  can be used to rebuild. Old parsed `.txt` files can be re-run through the corresponding `parse` task to check line counts and fill in completion records, but this cannot prove
  the old lines used the same source data/parser version. For a strict new build, use new parsed/tokenized/final directories.
- `assemble` and `variants` refuse to overwrite by default; resuming a half-finished product requires an explicit `--overwrite`. Overwrite authorization should be given only to
  rebuild directories, and not point to historical corpora still used by checkpoints/evaluation. Do not concurrently write to the same shard or final directory.
- Hub revisions, upstream Arrow cache versions, and parser/model weights are not all pinned yet. Therefore what is validated here is
  the data protocol, the provided indices, and the current build identity; it is not claimed that the entire historical training data or paper metrics have been reproduced.

Data regression entry points: `tests/test_pretraining_reproduction_pipeline.py`, `tests/test_pretraining_data_integrity.py`.

## 2. Pretraining campaign for all paper models

Configuration templates, pinned sources, and diagnostic configs are in the [configuration entry](../../train_configs/README.md).
All 29 original configs are in `train_configs/paper_sources/`, with SHA-256 pinned by the manifest;
generated configs do not depend on the weights directory, old config directories, or local audit materials.

List the registered model inventory (machine-readable identity is stored in the manifest):

```bash
python scripts/prepare_paper_pretraining.py --list
```

By default, 27 registered runs are generated; BBC Pause-1/2 correspond to the final paper's dedicated-SEP retraining;
the manifest additionally retains two historical repeat-token controls that are not selected by default. Generation only writes files, does not submit, and does not require data to be locally available:

```bash
python scripts/prepare_paper_pretraining.py \
  --campaign-dir artifacts/experiment/paper_pretraining_reproduction
```

Generate by experiment group:

```bash
python scripts/prepare_paper_pretraining.py --groups bbc-100m
python scripts/prepare_paper_pretraining.py --groups bbc-100m-baselines bbc-500m
python scripts/prepare_paper_pretraining.py --groups bbc-1b-supplementary
python scripts/prepare_paper_pretraining.py --groups fineweb-edu-1b
```

Retraining from scratch uniformly uses `max_duration=1ep`, `stop_at=2000000000`, `stop_after=null`,
and does not inherit the early-stopping limit of historical checkpoints; the Trainer typically ends at the end of the current epoch.
This user-confirmed policy is written to `protocol.json.stopping_policy`, without rewriting source configs.

Each run directory contains:

```text
runs/<model-id>/
├── config.yaml       # retraining config cleaned from checkpoint or hash-pinned original submitted config
├── launch.sh         # torchrun entry point that enforces schema and all local input checks before running
└── protocol.json     # paper identity, data representation, LR/batch/step, source and output SHA-256
```

The generator enforces the following gates:

1. checkpoint config's scale, seed, precision, grammar, LR, global batch, microbatch, dtype,
   pause id/sequence length, and mixing heads must match the frozen manifest;
2. clear the checkpoint's absolute old paths, evaluation-contaminated `data.paths`, old evaluator, `load_path`, and
   trainer/optimizer restore state;
3. BBC routes to standard single-stream or parse-aligned directories; FineWeb-Edu rebuilds the full 246 shard patterns;
4. by default do not overwrite an existing save folder; before launch, both perform a `TrainConfig` schema check and explicitly expand and check all
   plain-string training, parse-tree, evaluation, and tokenizer paths (historical YAML did not use a path resolver).

After obtaining the data, generate a fresh campaign with `--validate-data` before formal launch. The actual
world size of BBC 100M dedicated-SEP Pause is 8; the rest of BBC 100M/500M default to 4; FineWeb-Edu 1B is 64.
Per-run `gpu_count` takes precedence over the scale default. Multi-node `launch.sh` requires the scheduler to set `NNODES`,
`NPROC_PER_NODE`, `NODE_RANK`, `MASTER_ADDR`, and `MASTER_PORT` on each node, and the product of the first two must equal the registered
world size.

### 2.1 Model coverage

- BBC 100M: Terminal and the syntactic models Tree, TGTree, TG, TGNomask,
  TGNomask-Aug, Tree-NoONT, Tree-Compress, Tree-TripleCNT, Tree-Shuffle,
  TGNomask-Mix-TG, TGTree-Mix-TG; and the paper's dedicated-SEP Pause-1, Pause-2.
- BBC 100M architecture baselines: TreeReg-L9, Pushdown.
- BBC 500M: Terminal, Tree, TGTree, TGNomask-Aug.
- BBC 1B supplementary scaling: Terminal, Tree; these two are GPT-2/BBC models and must not be treated as FineWeb-Edu main experiments.
- FineWeb-Edu 1B main experiments: Terminal, Tree, TGTree, Pause-1, Pause-2.

The IDs for BBC 100M paper Pause-1/2 are `bbc_100m_pause1_sep` / `bbc_100m_pause2_sep`,
using dedicated SEP id 50261. The two submitted configs are stored in `train_configs/paper_sources/`, and the
original SHA-256 is verified during generation; SEP weights are not required to be locally available. FineWeb-Edu 1B continues to use dedicated SEP id 151673.

The historical `bbc_100m_pause1_repeat` / `bbc_100m_pause2_repeat` with `pause_token_id=null`
are repeat-token controls and do not correspond to the final paper Pause rows; generate them explicitly with:

```bash
python scripts/prepare_paper_pretraining.py --groups bbc-100m-historical
```

[`scripts/submit_pause_sep_pretrain.py`](../../scripts/submit_pause_sep_pretrain.py) is retained as the original
cluster submission and Step Law tool. To reproduce registered parameters, use the pinned configuration entry above; rerunning
the Step Law tool with a different GPU count may change the rounded global batch.

## 3. Validation

Task mapping, true checkpoint config cleaning, synthetic streaming assembly, linearization variants, and Step Law can be validated without downloading the full corpus:

```bash
PYTHONPATH=. python -m pytest -q \
  tests/test_pretraining_reproduction_pipeline.py \
  tests/test_paper_pause_protocol.py \
  tests/test_parse_pipeline_smoke.py \
  tests/test_make_tree_variant.py \
  tests/test_submit_pause_sep_pretrain.py \
  tests/test_step_law.py
```

Pretraining results and checkpoint identity are still uniformly backfilled to
the [paper results notes](../results/paper.md); do not create another manually maintained hyperparameter table in the README
that will drift.
